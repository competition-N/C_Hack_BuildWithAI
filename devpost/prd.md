# 팀 프로젝트 기여도 — Product Requirements

대학생 팀 프로젝트의 팀원, 팀장, 과제를 평가하는 사람이 공개 GitHub 저장소를 판단하고, 누가 실제로 일했는지 기능별 점수로 본다. 판단된 기여자는 누구나 볼 수 있는 기여 순위에 랜덤 닉네임으로 오르고, GitHub를 연결한 사람은 내 기여만 모아 본다.

Source: `scope.md > Who It's For`, `scope.md > The Unique Kernel`.

이 문서는 `3-prd`에서 승인한 뒤 `5-build`의 학습자 피드백으로 여러 번 바뀌었다. 아래 흐름과 화면은 지금 앱 기준이고, 처음 결정과 바뀐 이유는 **Product Decisions**에 남겼다.

## The Core Journey

Source: `scope.md > The Core Loop`, `scope.md > What "Working" Looks Like`.

1. 연다. 왼쪽 어두운 메뉴가 화면 왼쪽을 위에서 아래까지 차지하고, 메인·공개 프로젝트·로그인, 맨 아래에 "Language: KR/EN"이 있다. 메인에는 판단하기, 외부 전송·익명성·횟수 안내, "이 시스템이 하는 일" 설명이 있다.
2. 메인에서 공개 GitHub 저장소 주소를 넣고 판단하기를 누른다. 판단하는 동안 "판단하는 중입니다"가 보인다.
3. 결과가 나온다. 저장소 이름 아래 전체·기여도·문서 탭이 있다. 기여도에는 사람마다 순위, 점수, 기능별 점수("기능 (기술) 커밋 n × 난이도 d = 점수"), 근거가 있고, 이름은 GitHub 아이디 대신 랜덤 닉네임이다. 문서에는 기술 요약, 만든 기능, 난이도, 알고리즘이 있다.
4. 판단된 점수는 공개 프로젝트의 기여 순위에 더해진다. 누구나 닉네임으로 찾고, 이름을 누르면 그 사람이 한 프로젝트와 기능별 점수를 본다.
5. 가입하고 관리 > 설정에서 "GitHub로 연결"을 누르면 본인의 GitHub 아이디가 연결된다. 계정 공개를 켜면 순위에 내 닉네임으로 보인다.
6. 관리 > 프로젝트 관리에서 내 GitHub 저장소 목록 중 하나를 추가하면, 그 저장소의 내 점수·순위·기능별 점수와 저장소 요약을 본다. 재판단하기, 기여 순위에 공개 켜기/끄기, 목록에서 빼기가 있다.

데모에서 보여줄 장면은 메인에서 저장소 하나를 판단해 기능별 점수와 AI 에이전트 커밋 합치기가 보이는 화면, 다시 판단해도 같은 점수, 기여 순위 검색, GitHub 연결 후 프로젝트 관리, 언어 바꾸기다.

## Screens and Layout

왼쪽 열은 화면 왼쪽 전체를 차지한다. 결과 탭과 저장소 이름은 왼쪽 열의 오른쪽 본문 안에만 있다.

- **메인** — 판단하기, 안내, 결과(전체·기여도·문서), "이 시스템이 하는 일".
- **공개 프로젝트** — 사람별 기여 순위와 닉네임 검색. 이름을 누르면 사람 화면.
- **로그인** — 로그인과 가입. 로그인하면 이 자리가 "관리"(설정, 프로젝트 관리) 펼침 메뉴로 바뀐다.
- **관리 > 설정** — GitHub 연결, 언어, 닉네임, 계정 공개, 비밀번호 변경, 로그아웃, 계정 삭제.
- **관리 > 프로젝트 관리** — 왼쪽에 내 프로젝트 목록, 오른쪽에 저장소 추가(내 GitHub 저장소 목록) 또는 열린 프로젝트의 상세와 설정.
- **Language 버튼** — 왼쪽 메뉴 맨 아래. 누를 때마다 한국어와 영어가 바뀐다.

## Look and Feel

보는 느낌은 [이환 사키리 가이드](https://alkapa.gg/neverness-to-everness/characters/sagiri)와 비슷하다. 글자, 색, 참고 사이트에서 가져온 구성 요소는 더 정하지 않았다.

정해진 배치는 이것이다. 왼쪽이 왼쪽을 위에서 아래까지 먹고, 상단은 그 왼쪽에 관여하지 않는다. 프로젝트 이름과 서브 카테고리는 왼쪽 열 밖의 위쪽에만 놓인다.

`5-build` 피드백: "AI 티를 빼고 깔끔하고 이쁘게", 그리고 `.cursor/rules`의 디자인 규칙을 따른다. 색·글자·간격은 `design/tokens/`의 값만 쓴다. 무채색 바탕에 강조색 하나, 그라데이션과 그림자 없음, 왼쪽 정렬, 글자 크기와 구분선으로 위계를 만든다. WCAG 2.1 AA 대비, 보이는 초점, 입력칸마다 보이는 라벨을 지킨다.

## Features and Behavior

### 메인

오른쪽 메인은 이 시스템에 대한 설명을 보여 준다.

- [ ] 메인을 열면 설명이 보인다.
- [ ] 왼쪽에는 메인, 공개 프로젝트, 로그인이 있다.
- [ ] 메인에 "이 시스템이 하는 일"이 보인다: 판단 순서, 나오는 결과와 점수에 넣지 않는 것, 되는 것과 안 되는 것, 난이도 기준. 판단 결과가 있으면 결과 아래에 접혀 있다.
- [ ] 왼쪽 메뉴 맨 아래 "Language: KR"을 누르면 "Language: EN"으로 바뀌고 화면 전체가 영어가 된다. 다시 누르면 한국어로 돌아온다. 계정 설정에 가지 않아도 되고, 로그인한 상태면 계정 언어도 함께 바뀐다.
- [ ] 판단하기 아래에 안내가 보인다: 커밋 메시지·README 일부·바뀐 코드 일부가 외부 AI 서비스(Groq)로 전송된다는 것, 결과와 순위에는 랜덤 닉네임이 보인다는 것, 한 시간에 판단할 수 있는 횟수(3번)와 남은 횟수.
- [ ] 판단 결과의 사람 칸에는 GitHub 아이디 대신 순위와 같은 이름(공개 계정은 닉네임, 나머지는 랜덤 닉네임)이 보이고, 내 기록에는 "나"가 붙는다.
- [ ] 한 시간에 4번째 판단은 "판단은 계정과 접속한 네트워크(IP)마다 한 시간에 3번까지 할 수 있습니다. N분 뒤에 다시 시도해 주세요."로 거절된다. 같은 IP에서 계정을 새로 만들어도 IP 한도를 넘으면 거절된다. 주소 형식이 틀린 요청은 횟수에 세지 않는다.
- [ ] 커밋 메시지에 점수를 정하라는 문장이 있거나, 오타·문서 수정 같은 작은 변경이 높은 난이도를 받거나, 거의 모든 커밋이 최고 난이도면, 그 사람에게 "점수 확인 필요"와 이유가 붙는다. 점수는 바뀌지 않는다. 기여 순위의 닉네임 옆에는 "확인 필요"가 보인다.
- [ ] 이미 판단한 커밋은 저장된 결과를 다시 써서, 같은 저장소를 다시 판단해도 새 커밋이 없으면 점수가 같다.

### 프로젝트 목록

`5-build` 피드백으로 바뀌었다. 로그인은 아이디와 비밀번호다. 관리 > 프로젝트 관리는 GitHub를 연결한 사람의 **내 기여만** 모아 본다. GitHub를 연결하지 않았으면 연결하라는 안내만 보인다.

- [ ] 아이디와 비밀번호가 맞으면 로그인되고, 틀리면 들어가지 않는다.
- [ ] GitHub를 연결하지 않았으면 프로젝트 관리에 "먼저 GitHub를 연결해 주세요"와 설정으로 가는 버튼만 보인다.
- [ ] 목록의 항목마다 저장소 이름과 내 점수가 보인다. 목록이 비어 있으면 추가하기만 보인다.

### 추가하기

프로젝트 관리의 추가하기에는 연결한 GitHub 아이디의 공개 저장소 목록이 나온다. 내 저장소, 협업자로 들어간 저장소, 내가 커밋한 다른 사람의 공개 저장소가 함께 나오고, 이름으로 찾을 수 있다. 저장소를 고르면 저장소 전체를 판단한 뒤 내 GitHub 아이디의 기여가 있을 때만 목록에 넣는다. 목록에 없는 저장소는 접힌 칸에서 주소로 넣는다. 웹훅 연결과 비공개 저장소는 없다.

Source: `scope.md > The POC Boundary`.

- [ ] 추가하기에 내 공개 저장소 목록이 종류 표시(내 저장소, 협업자, 커밋한 저장소)와 함께 나오고, 이미 추가한 저장소는 "추가됨"이다.
- [ ] 저장소 이름으로 목록을 거를 수 있다.
- [ ] 내가 기여한 공개 저장소를 추가하면 목록에 들어가고 내 점수가 보인다.
- [ ] 내가 기여하지 않은 저장소는 "기여자 중에 (아이디)이(가) 없어서 추가하지 않았습니다"로 거절된다.
- [ ] 웹훅을 연결하는 조작은 보이지 않는다.

### 판단 결과

판단은 요청 안에서 끝나고, 그동안 "진행중"이 보인다. 팀원이 많으면 1~2분 걸릴 수 있다. 실패하면 "실패"와 실패 사유가 보이고, 이미 판단된 저장소였다면 이전 결과가 남는다.

- [ ] 판단하는 동안 "진행중"이 보이고 버튼이 잠긴다.
- [ ] 실패하면 "실패"와 실패 사유가 보인다.
- [ ] 재판단이 실패해도 이전 결과는 남는다.

### 기여도

메인의 기여도에는 순위, 사람, 점수, 기능별 점수, 근거가 있다. `5-build` 피드백으로 점수는 기능 단위로 나눠 매긴다. 기능 점수 = 그 기능의 커밋 수 × 그 기능의 코드 난이도(1~5)이고, 사람 점수 = 기능 점수의 합이다. 기능마다 쓰인 기술 하나가 붙는다. PR은 안의 커밋이 이미 점수에 들어가므로 근거로만 보여 준다. 바뀐 줄 수와 파일 수도 근거로만 보여 준다.

Source: `scope.md > The Unique Kernel`.

- [ ] 사람마다 "기능 이름 (기술) 커밋 n × 난이도 d = 점수"가 기능 수만큼 보이고, 그 합이 점수다.
- [ ] 모델이 읽지 않은 커밋은 점수에 넣지 않는다. `5-build` 피드백으로 평균 난이도를 적용하던 방식을 없앴다. 근거에 "모델이 읽지 않은 커밋 N개는 점수에 넣지 않음"이 보인다. 커밋이 많은 6명 밖의 사람도 같은 이유로 0점이다.
- [ ] 공동 작성자(Co-authored-by)가 적힌 AI 에이전트 커밋은 그 사람에게 합쳐지고 "AI 에이전트 N건 포함"이 보인다.
- [ ] 근거에 커밋 수, 합쳐진·열린 PR 수, 모델이 기능으로 나눈 커밋 수, 코드를 읽은 커밋의 파일 수와 추가·삭제 줄 수가 보인다.

### 문서

문서에는 기술 요약, 만든 기능, 난이도, 알고리즘이 있다. 이 내용은 기여도의 점수와 한 일을 읽는 근거다. `5-build` 피드백으로 기술 상세는 메인과 내 프로젝트 관리에서 본다. 기여 순위와 사람 화면에는 나오지 않는다.

Source: `scope.md > The Unique Kernel`.

- [ ] 완료된 프로젝트의 문서에서 기술 요약, 만든 기능, 난이도, 알고리즘이 보인다. 만든 기능은 사람별 한 일과 커밋 내역을 합쳐 프로젝트 전체에서 무엇을 만들었는지 정리한 목록이다.

### 설정

열린 내 프로젝트 맨 아래의 설정에 "기여 순위에 공개"와 "목록에서 빼기"가 있다. `5-build` 피드백으로 프로젝트별 공개 설정을 다시 넣었다. 공개를 끄면 **그 저장소의 내 점수만** 기여 순위와 내 사람 화면에서 빠진다. 같은 저장소의 다른 팀원 점수는 그 사람들의 몫이라 숨기지 않는다. 처음 값은 공개다.

- [ ] 공개를 끄면 내 총점에서 그 저장소 점수가 빠지고, 내 사람 화면에서 그 저장소가 사라진다. 다른 사람의 점수는 그대로다.
- [ ] 공개를 끈 저장소는 내 프로젝트 목록에 "비공개" 표시가 붙고, 프로젝트 관리에서는 계속 보인다.
- [ ] 목록에서 빼면 프로젝트 관리 목록에서만 빠진다. 공개를 꺼 둔 상태였다면 빼는 순간 내 점수가 기여 순위에 다시 나온다.

### 공개 프로젝트

`5-build` 피드백으로 프로젝트별 카드 대신 **사람별 기여 순위**가 되었다. 메인이든 프로젝트 관리든 한 번이라도 판단된 저장소의 GitHub 기여자는 모두 순위에 오른다. 점수는 그 사람이 나온 모든 저장소 점수의 합이다. GitHub를 연결하고 계정 공개를 켠 사람만 닉네임으로 보이고, 나머지는 같은 사람에게 늘 같은 랜덤 닉네임(예: "조용한수달#3fa2")으로 보인다. AI 에이전트 계정은 순위에 넣지 않는다.

- [ ] 순위, 닉네임, 총점, 프로젝트 수가 보인다. 판단된 저장소가 없으면 "정보 없음"이다. 0점인 사람은 순위에 나오지 않는다.
- [ ] 닉네임 검색은 화면에 보이는 이름으로만 된다. GitHub 아이디로는 찾을 수 없다.
- [ ] 닉네임을 누르면 그 사람의 전체 순위, 총점, 프로젝트별 점수와 기능별 점수가 보인다.
- [ ] 순위와 사람 화면에는 GitHub 아이디와 기술 상세가 나오지 않는다.

### 관리

로그인하면 왼쪽의 로그인이 사라지고 관리가 생긴다. 관리를 누르면 아래로 설정과 프로젝트 관리가 펼쳐진다. `5-build` 피드백으로 추가했다.

- [ ] 로그인 전에는 로그인만, 로그인 후에는 관리만 보인다.
- [ ] 관리를 누르면 설정과 프로젝트 관리가 펼쳐지고, 다시 누르면 접힌다.
- [ ] 프로젝트 관리에는 내 프로젝트 목록과 추가하기가 있다.
- [ ] 프로젝트를 열면 추가하기 대신 재판단하기, 목록에서 빼기, 닫기가 보이고, 내 점수, 저장소 안 순위, 기능별 점수, 근거, 그리고 그 저장소의 기술 요약·만든 기능·난이도·알고리즘이 보인다. 다른 팀원의 점수는 나오지 않는다. 재판단하기는 같은 저장소를 다시 판단하고, 끝나면 "다시 판단했습니다." 또는 실패 사유를 보여 준다.

### 계정 설정

관리 > 설정은 계정 설정이다. GitHub 연결, 닉네임 변경, 계정 공개 켜기/끄기, 비밀번호 변경, 계정 삭제, 로그아웃이 있다. 계정 공개는 처음에 꺼져 있다.

- [ ] "GitHub로 연결"을 누르면 GitHub에서 로그인한 본인의 아이디만 연결된다. 이미 다른 계정에 연결된 GitHub 계정은 거절한다. 연결 해제도 된다.
- [ ] 닉네임은 2~20자이고, 다른 사람이 쓰는 닉네임과 `#`이 들어간 닉네임은 거절한다.
- [ ] 계정 공개를 켜면 기여 순위에 닉네임이, 끄면 랜덤 닉네임이 보인다.
- [ ] 비밀번호는 지금 비밀번호가 맞아야 바뀌고, 바뀌면 다른 기기의 로그인이 끊긴다.
- [ ] 계정 삭제는 비밀번호 확인 후 계정과 프로젝트 관리 목록을 지운다. 판단된 저장소의 GitHub 기록은 남고 랜덤 닉네임으로 보인다.
- [ ] 언어에서 한국어·English를 고르면 화면 전체와 서버 안내 문장, 기능 이름, 프로젝트 요약이 그 언어로 바뀌고, 다음에 로그인해도 유지된다. 로그인하지 않은 사람에게는 브라우저 언어로 보인다. 랜덤 닉네임도 같은 짝의 영어 이름("QuietOtter#3fa2")으로 보인다.

## States and Boundaries

- **처음 열었을 때** — 메인 안내와 "이 시스템이 하는 일". 판단된 저장소가 없으면 기여 순위는 "아직 판단된 저장소가 없습니다"다. 언어는 브라우저 언어를 따른다.
- **판단하는 중** — "판단하는 중입니다"가 보이고 버튼이 잠긴다. 팀원이 많으면 1~2분 걸린다.
- **실패** — "판단하지 못했습니다"와 이유(주소 형식, 없는 저장소, GitHub 한도 등). 이미 판단된 저장소였다면 이전 결과가 남는다.
- **횟수 초과** — 계정이나 IP의 한 시간 4번째 판단은 남은 분과 함께 거절된다.
- **점수가 증거와 맞지 않을 때** — 점수는 그대로 두고 "점수 확인 필요"와 이유를 보여 준다. 판단은 사람이 커밋을 직접 보고 한다.
- **모델이 응답하지 않을 때** — 이미 읽은 커밋은 저장된 결과로 점수가 나오고, 새 커밋은 다음 판단에서 다시 읽는다. 요약은 README와 사용 언어로 대신한다.
- **다시 판단할 때** — 이미 읽은 커밋은 저장된 결과를 써서 같은 점수다. 새 커밋만 새로 읽는다.
- **빈 프로젝트 관리** — GitHub가 연결되지 않았으면 연결 안내만, 연결됐으면 저장소 추가만 보인다.
- **누가 무엇을 보나** — 판단 결과와 순위는 누구나 본다. GitHub 아이디는 어디에도 보이지 않고, GitHub를 연결해 계정 공개를 켠 사람만 닉네임으로 보인다. 프로젝트 관리는 본인 것만 본다.

## Product Decisions

- 로그인, 프로젝트 목록, 공개 프로젝트를 지금 넣는다. 범위가 커지는 것은 상관없다고 했고, 판단 결과와 같이 가기로 했다.
- 로그인할 때 사람은 아무것도 하지 않는다고 정했다가, `4-spec`에서 아이디와 비밀번호가 있는 계정을 지금 넣기로 바꾸었다. 공유는 로그인한 사람이 프로젝트를 등록한 뒤 설정에서 켠다.
- 목록이 비어 있으면 추가하기가 생긴다.
- 추가하기는 공개 저장소 주소다. 웹훅은 나중으로 미룬다.
- 주소를 넣으면 진행이 되고 프로젝트 목록으로 이동한다.
- 상태는 진행중, 완료, 실패다. 완료는 모든 내용의 갱신이 끝났을 때다.
- 안의 서브 카테고리는 전체, 기여도(순위, 세부 점수, 한 일), 문서(기술 요약, 난이도, 알고리즘), 설정이다.
- 설정은 삭제, 연동 확인, 공개/비공개다. 공개는 로그인하지 않은 사람을 포함해 다른 사람이 보게 할지를 정한다.
- 공개된 것이 없으면 "정보 없음"이다.
- 지금은 공개 저장소만 된다. 비공개 저장소는 나중에 웹훅으로 연동한다.
- 보는 느낌은 사키리 가이드 페이지와 비슷하게 가되, 왼쪽은 왼쪽 전체를 차지하고 상단은 왼쪽에 들어가지 않는다.

`5-build`에서 바뀐 결정 (학습자 피드백 순서대로):

- 프로젝트별 카드였던 공개 프로젝트를 **사람별 기여 순위**로 바꿨다. 판단된 모든 저장소의 GitHub 기여자가 오르고, 검색과 사람 화면이 있다. `scope.md > Later`의 "전 세계 랭킹"을 앞당긴 것이다.
- 점수를 "커밋 수 + PR 수"에서 "작업량 × 난이도"로, 다시 **기능마다 (커밋 수 × 코드 난이도)의 합**으로 바꿨다. PR은 안의 커밋과 겹쳐 점수에서 뺐다.
- 모델이 읽지 않은 커밋에 평균 난이도를 매기던 것을 없애고, **모델이 읽은 커밋만** 점수에 넣는다.
- 같은 저장소의 점수가 판단할 때마다 바뀌어, **커밋별 판단 결과를 저장**하고 새 커밋만 읽게 했다.
- Cursor 같은 **AI 에이전트 커밋은 공동 작성자(Co-authored-by)에게 합친다**. 에이전트 커밋 수는 따로 저장해 나중에 설정으로 넣고 뺄 수 있게 했다.
- 로그인 화면 자리를 로그인 후 **관리(설정, 프로젝트 관리)** 메뉴로 바꿨다.
- 프로젝트 관리는 GitHub 아이디를 직접 입력하면 남의 점수를 가져갈 수 있어, **GitHub OAuth로 본인 확인**을 한 뒤 내 기여만 본다. 저장소는 주소를 넣는 대신 내 GitHub 저장소 목록에서 고른다.
- 순위에 보이는 이름은 GitHub 아이디 대신 **랜덤 닉네임**이고, 메인 판단 결과도 같다. 계정 공개를 켠 사람만 닉네임으로 보인다.
- 프로젝트별 공유 설정을 없앴다가, **"기여 순위에 공개" 켜기/끄기**로 다시 넣었다. 끄면 그 저장소의 내 점수만 빠진다.
- 판단은 **한 시간에 3번**, 외부 AI 전송 안내, 점수 조작 문장 제거, 보안 헤더를 넣었다.
- 계정을 여러 개 만들어 판단 횟수를 늘릴 수 있어 **IP로도 함께 센다**. 조작 문장 제거는 패턴 방식이라 다 잡지 못해서, 모델이 매긴 점수가 증거와 맞지 않으면 **"점수 확인 필요" 경고**를 붙인다. 오탐이 있을 수 있어 점수를 자동으로 깎지는 않는다.
- **한국어·영어**를 넣었다. 계정 설정과 왼쪽 맨 아래 Language 버튼으로 바꾼다.
- 디자인은 `.cursor/rules`의 디자인 규칙과 `design/tokens/`로 다시 만들었다.

## What We're Building

- 메인의 저장소 판단: 기능별 점수, 근거, AI 에이전트 커밋 합치기, 저장소 요약(두 언어), 시스템 설명, 외부 전송·익명성·횟수 안내.
- 커밋별 판단 결과 저장, 모델이 읽은 커밋만 점수에 넣기, 점수 조작 문장 제거, 점수 확인 필요 경고, 계정·IP별 한 시간 3번 제한.
- 공개 프로젝트의 사람별 기여 순위, 닉네임 검색, 사람 화면. GitHub 아이디는 보이지 않는다.
- 가입·로그인, GitHub OAuth 연결, 닉네임, 계정 공개, 언어, 비밀번호 변경, 로그아웃, 계정 삭제.
- 프로젝트 관리: 내 GitHub 저장소 목록에서 추가, 내 점수와 저장소 요약, 재판단, 기여 순위 공개 켜기/끄기, 목록에서 빼기.
- 한국어·영어 화면과 Language 버튼.

## Deferred From the POC

- **비공개 저장소와 웹훅** — 읽기 전용 GitHub App이 필요하고, 비공개 결과를 순위에서 어떻게 다룰지 정해야 한다. 제출 뒤로 미뤘다.
- **AI 에이전트 커밋 포함 여부 설정** — 에이전트 커밋 수는 이미 따로 저장한다. 설정 화면만 남았다.
- **커밋을 잘게 쪼개 점수를 올리는 것 막기** — 아직 막지 않는다.
- **파일로 프로젝트나 문서를 직접 올리기** — Source: `scope.md > Later`.
- **GitLab 등 GitHub 밖 연동** — Source: `scope.md > Later`.

## Possible Later Enhancements

비공개 저장소를 읽기 전용 GitHub App과 웹훅으로 붙이기, 에이전트 커밋 포함 설정, 커밋 쪼개기 방지, 파일 업로드, GitLab 연동은 나중에 할 수 있는 일이다.

## Non-Goals

- **역할마다 다른 화면이나 권한** — 팀원, 팀장, 평가자는 같은 결과를 본다. Source: `scope.md > Explicitly Cut`.
- **GitHub 아이디를 공개하는 것** — 순위와 판단 결과에는 랜덤 닉네임이나 본인이 공개한 닉네임만 보인다.
- **코드를 실행해 보는 검사** — 모델은 바뀐 코드 일부를 읽기만 한다.

## Open Questions

- 실패 사유는 주소 형식, 없는 저장소, GitHub 한도, GitHub 읽기 실패 네 가지로 정했다.
- 계정 닉네임이 GitHub 아이디와 같으면 계정 공개를 켰을 때 사실상 익명이 아니다. 막을지는 정하지 않았다.
