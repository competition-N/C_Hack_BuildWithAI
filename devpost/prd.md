# 팀 프로젝트 기여도 — Product Requirements

대학생 팀 프로젝트의 팀원, 팀장, 과제를 평가하는 사람이 공개 GitHub 저장소를 연결하고, 누가 실제로 일했는지 순위·점수·한 일로 본다. 로그인을 하지 않은 사람도, 공개로 둔 프로젝트는 볼 수 있다.

Source: `scope.md > Who It's For`, `scope.md > The Unique Kernel`.

## The Core Journey

Source: `scope.md > The Core Loop`, `scope.md > What "Working" Looks Like`.

1. 연다. 왼쪽은 화면 왼쪽을 위에서 아래까지 차지하고, 메인·공개 프로젝트·로그인이 있다. 오른쪽 메인은 이 시스템에 대한 설명이다. 상단 줄이 있을 때는 왼쪽 영역에 들어가지 않는다.
2. 로그인에서 아이디와 비밀번호를 입력한다. 맞으면 그 사람의 프로젝트 목록이 나온다. 아무것도 없으면 추가하기가 있다.
3. 추가하기를 누르고 공개 저장소 주소를 넣으면 진행이 시작되고, 프로젝트 목록으로 돌아간다. 그 항목은 진행중이다.
4. 항목을 연다. 왼쪽 카테고리는 그대로다. 오른쪽 위에는 프로젝트 이름과 서브 카테고리가 있다. 전체, 기여도, 문서, 설정. 이 상단은 왼쪽 영역을 침범하지 않는다.
5. 처음이면 전체에는 결과만 있다. 진행중이면 "진행중", 실패면 "실패"와 실패 사유. 갱신이 되지 않았으면 이전에 저장된 내용이 그대로다. 모든 내용의 갱신이 끝나면 완료가 되고, 전체에는 갱신된 내용이 보이며 기여도와 문서에서 순위, 세부 점수, 한 일, 기술 요약, 난이도, 알고리즘을 본다.
6. 설정에서 공개로 두면, 로그인하지 않은 사람을 포함한 다른 사람이 공개 프로젝트에서 그 프로젝트의 설명과 기여도를 본다. 공개된 것이 없으면 공개 프로젝트는 "정보 없음"이다.

데모에서 보여줄 장면은 공개 저장소 주소 하나를 넣은 뒤, 목록의 상태가 바뀌고, 완료된 항목에서 기여도와 문서가 함께 보이는 화면이다.

## Screens and Layout

왼쪽 열은 화면 왼쪽 전체를 차지한다. 프로젝트 안에 들어갔을 때 생기는 상단(프로젝트 이름, 서브 카테고리)은 왼쪽 열의 오른쪽 영역에만 있다.

- **메인** — 이 시스템이 무엇인지에 대한 설명.
- **공개 프로젝트** — 공개로 둔 프로젝트의 설명과 기여도. 없으면 "정보 없음".
- **로그인** — 아이디와 비밀번호를 입력한다. 맞으면 그 사람의 프로젝트 목록. 비어 있으면 추가하기.
- **추가하기** — 공개 저장소 주소를 넣는 단계. 진행이 시작되면 목록으로 돌아간다.
- **프로젝트 안** — 전체, 기여도, 문서, 설정.

## Look and Feel

보는 느낌은 [이환 사키리 가이드](https://alkapa.gg/neverness-to-everness/characters/sagiri)와 비슷하다. 글자, 색, 참고 사이트에서 가져온 구성 요소는 더 정하지 않았다.

정해진 배치는 이것이다. 왼쪽이 왼쪽을 위에서 아래까지 먹고, 상단은 그 왼쪽에 관여하지 않는다. 프로젝트 이름과 서브 카테고리는 왼쪽 열 밖의 위쪽에만 놓인다.

## Features and Behavior

### 메인

오른쪽 메인은 이 시스템에 대한 설명을 보여 준다.

- [ ] 메인을 열면 설명이 보인다.
- [ ] 왼쪽에는 메인, 공개 프로젝트, 로그인이 있다.

### 프로젝트 목록

`5-build` 피드백으로 바뀌었다. 로그인은 아이디와 비밀번호다. 관리 > 프로젝트 관리는 GitHub를 연결한 사람의 **내 기여만** 모아 본다. GitHub를 연결하지 않았으면 연결하라는 안내만 보인다.

- [ ] 아이디와 비밀번호가 맞으면 로그인되고, 틀리면 들어가지 않는다.
- [ ] GitHub를 연결하지 않았으면 프로젝트 관리에 "먼저 GitHub를 연결해 주세요"와 설정으로 가는 버튼만 보인다.
- [ ] 목록의 항목마다 저장소 이름과 내 점수가 보인다. 목록이 비어 있으면 추가하기만 보인다.

### 추가하기

프로젝트 관리의 추가하기에는 연결한 GitHub 아이디의 공개 저장소 목록이 나온다. 내 저장소, 협업자로 들어간 저장소, 내가 커밋한 다른 사람의 공개 저장소가 함께 나오고, 이름으로 찾을 수 있다. 저장소를 고르면 저장소 전체를 판단한 뒤 내 GitHub 아이디의 기여가 있을 때만 목록에 넣는다. 목록에 없는 저장소는 접힌 칸에서 주소로 넣는다. 웹훅 연결과 비공개 저장소는 없다.

Source: `scope.md > The POC Boundary`.

- [ ] 추가하기에 내 공개 저장소 목록이 종류 표시(내 저장소, 협업자, 커밋한 저장소)와 함께 나오고, 이미 추가한 저장소는 "추가됨"이다.
- [ ] 저장소 이름으로 목록을 거를 수 있다.
- [ ] 내가 기여한 공개 저장소를 추가하면 목록에 들어가고 내 점수가 보인다.
- [ ] 내가 기여하지 않은 저장소는 "기여자 중에 (아이디)이(가) 없어서 추가하지 않았습니다"로 거절된다.
- [ ] 웹훅을 연결하는 조작은 보이지 않는다.

### 판단 결과

판단은 요청 안에서 끝나고, 그동안 "진행중"이 보인다. 팀원이 많으면 1~2분 걸릴 수 있다. 실패하면 "실패"와 실패 사유가 보이고, 이미 판단된 저장소였다면 이전 결과가 남는다.

- [ ] 판단하는 동안 "진행중"이 보이고 버튼이 잠긴다.
- [ ] 실패하면 "실패"와 실패 사유가 보인다.
- [ ] 재판단이 실패해도 이전 결과는 남는다.

### 기여도

메인의 기여도에는 순위, 사람, 점수, 기능별 점수, 근거가 있다. `5-build` 피드백으로 점수는 기능 단위로 나눠 매긴다. 기능 점수 = 그 기능의 커밋 수 × 그 기능의 코드 난이도(1~5)이고, 사람 점수 = 기능 점수의 합이다. 기능마다 쓰인 기술 하나가 붙는다. PR은 안의 커밋이 이미 점수에 들어가므로 근거로만 보여 준다. 바뀐 줄 수와 파일 수도 근거로만 보여 준다.

Source: `scope.md > The Unique Kernel`.

- [ ] 사람마다 "기능 이름 (기술) 커밋 n × 난이도 d = 점수"가 기능 수만큼 보이고, 그 합이 점수다.
- [ ] 모델이 읽지 못한 커밋은 "모델이 읽지 않은 커밋 (평균 난이도 적용)"으로 따로 보인다.
- [ ] 공동 작성자(Co-authored-by)가 적힌 AI 에이전트 커밋은 그 사람에게 합쳐지고 "AI 에이전트 N건 포함"이 보인다.
- [ ] 근거에 커밋 수, 합쳐진·열린 PR 수, 모델이 기능으로 나눈 커밋 수, 코드를 읽은 커밋의 파일 수와 추가·삭제 줄 수가 보인다.

### 문서

문서에는 기술 요약, 만든 기능, 난이도, 알고리즘이 있다. 이 내용은 기여도의 점수와 한 일을 읽는 근거다. `5-build` 피드백으로 기술 상세는 메인에서만 본다. 프로젝트 관리와 기여 순위에는 나오지 않는다.

Source: `scope.md > The Unique Kernel`.

- [ ] 완료된 프로젝트의 문서에서 기술 요약, 만든 기능, 난이도, 알고리즘이 보인다. 만든 기능은 사람별 한 일과 커밋 내역을 합쳐 프로젝트 전체에서 무엇을 만들었는지 정리한 목록이다.

### 설정

`5-build` 피드백으로 프로젝트별 설정(공유, 연동 확인)은 없앴다. 열린 내 프로젝트에는 재판단하기, 목록에서 빼기, 닫기만 있다. 목록에서 빼도 기여 순위의 GitHub 기록은 남는다.

- [ ] 목록에서 빼면 프로젝트 관리 목록에서만 빠지고, 기여 순위의 점수는 그대로다.

### 공개 프로젝트

`5-build` 피드백으로 프로젝트별 카드 대신 **사람별 기여 순위**가 되었다. 메인이든 프로젝트 관리든 한 번이라도 판단된 저장소의 GitHub 기여자는 모두 순위에 오른다. 점수는 그 사람이 나온 모든 저장소 점수의 합이다. GitHub를 연결하고 계정 공개를 켠 사람만 닉네임으로 보이고, 나머지는 같은 사람에게 늘 같은 랜덤 닉네임(예: "조용한수달#3fa2")으로 보인다. AI 에이전트 계정은 순위에 넣지 않는다.

- [ ] 순위, 닉네임, 총점, 프로젝트 수가 보인다. 판단된 저장소가 없으면 "정보 없음"이다.
- [ ] 닉네임 검색은 화면에 보이는 이름으로만 된다. GitHub 아이디로는 찾을 수 없다.
- [ ] 닉네임을 누르면 그 사람의 전체 순위, 총점, 프로젝트별 점수와 기능별 점수가 보인다.
- [ ] 순위와 사람 화면에는 GitHub 아이디와 기술 상세가 나오지 않는다.

### 관리

로그인하면 왼쪽의 로그인이 사라지고 관리가 생긴다. 관리를 누르면 아래로 설정과 프로젝트 관리가 펼쳐진다. `5-build` 피드백으로 추가했다.

- [ ] 로그인 전에는 로그인만, 로그인 후에는 관리만 보인다.
- [ ] 관리를 누르면 설정과 프로젝트 관리가 펼쳐지고, 다시 누르면 접힌다.
- [ ] 프로젝트 관리에는 내 프로젝트 목록과 추가하기가 있다.
- [ ] 프로젝트를 열면 추가하기 대신 재판단하기, 목록에서 빼기, 닫기가 보이고, 내 점수, 저장소 안 순위, 기능별 점수, 근거가 보인다. 재판단하기는 같은 저장소를 다시 판단하고, 끝나면 "다시 판단했습니다." 또는 실패 사유를 보여 준다.

### 계정 설정

관리 > 설정은 계정 설정이다. GitHub 연결, 닉네임 변경, 계정 공개 켜기/끄기, 비밀번호 변경, 계정 삭제, 로그아웃이 있다. 계정 공개는 처음에 꺼져 있다.

- [ ] "GitHub로 연결"을 누르면 GitHub에서 로그인한 본인의 아이디만 연결된다. 이미 다른 계정에 연결된 GitHub 계정은 거절한다. 연결 해제도 된다.
- [ ] 닉네임은 2~20자이고, 다른 사람이 쓰는 닉네임과 `#`이 들어간 닉네임은 거절한다.
- [ ] 계정 공개를 켜면 기여 순위에 닉네임이, 끄면 랜덤 닉네임이 보인다.
- [ ] 비밀번호는 지금 비밀번호가 맞아야 바뀌고, 바뀌면 다른 기기의 로그인이 끊긴다.
- [ ] 계정 삭제는 비밀번호 확인 후 계정과 프로젝트 관리 목록을 지운다. 판단된 저장소의 GitHub 기록은 남고 랜덤 닉네임으로 보인다.

## States and Boundaries

- **처음 열었을 때** — 메인 설명과 왼쪽 카테고리. 프로젝트 목록은 비어 있고 추가하기가 있다. 공개 프로젝트는 "정보 없음"이다.
- **빈 목록** — 추가하기만 있다.
- **진행중** — 목록에 진행중. 처음 열면 전체에 "진행중".
- **완료** — 목록에 완료. 전체에는 갱신된 내용이 있고, 기여도와 문서에 각 부분이 있다.
- **실패** — 목록에 실패. 전체에 "실패"와 실패 사유.
- **갱신이 안 된 경우** — 이전 내용이 남는다.
- **다시 열었을 때** — 저장된 프로젝트와 이전 결과가 남아 있다.
- **누가 보나** — 팀원, 팀장, 평가자는 같은 결과를 본다. 로그인하지 않은 사람은 공개로 둔 프로젝트만 본다.
- **완료의 전체** — 갱신된 내용 전체를 보여 주고, 기여도·문서는 그 안의 해당 부분을 보여 준다. 초안 승인으로 확정했다.

## Product Decisions

- 로그인, 프로젝트 목록, 공개 프로젝트를 지금 넣는다. 범위가 커지는 것은 상관없다고 했고, 판단 결과와 같이 가기로 했다.
- 로그인할 때 사람은 아무것도 하지 않는다고 정했다가, `4-spec`에서 아이디와 비밀번호가 있는 계정을 지금 넣기로 바꾸었다. 공유는 로그인한 사람이 프로젝트를 등록한 뒤 설정에서 켠다.
- 목록이 비어 있으면 추가하기가 생긴다.
- 추가하기는 공개 저장소 주소다. 웹훅은 나중으로 미룬다.
- 주소를 넣으면 진행이 되고 프로젝트 목록으로 이동한다.
- 상태는 진행중, 완료, 실패다. 완료는 모든 내용의 갱신이 끝났을 때다.
- 안의 서브 카테고리는 전체, 기여도(순위, 세부 점수, 한 일), 문서(기술 요약, 난이도, 알고리즘), 설정이다.
- 설정은 삭제, 연동 확인, 공개/비공개다. 공개는 로그인하지 않은 사람을 포함해 다른 사람이 보게 할지를 정한다.
- 공개된 것이 없으면 "정보 없음"이다.
- 지금은 공개 저장소만 된다. 비공개 저장소는 나중에 웹훅으로 연동한다.
- 보는 느낌은 사키리 가이드 페이지와 비슷하게 가되, 왼쪽은 왼쪽 전체를 차지하고 상단은 왼쪽에 들어가지 않는다.

## What We're Building

- 왼쪽 전체 높이의 메인, 공개 프로젝트, 로그인.
- 아이디와 비밀번호로 로그인하고, 그 사람의 프로젝트 목록을 본다. 빈 목록의 추가하기.
- 공개 저장소 주소를 넣고 진행중으로 목록에 돌아오기.
- 진행중, 완료, 실패. 실패 사유. 갱신이 없으면 이전 내용.
- 완료 후 기여도의 순위, 세부 점수, 한 일.
- 완료 후 문서의 기술 요약, 난이도, 알고리즘.
- 설정의 삭제, 연동 확인, 공개/비공개.
- 공개 프로젝트에서 로그인하지 않은 사람도 공개 항목의 설명과 기여도를 보기. 없으면 "정보 없음".

## Deferred From the POC

- **웹훅 연결** — 추가하기에 같이 두자고 했다가, 비공개 저장소와 함께 나중으로 미뤘다.
- **비공개 저장소** — 지금은 공개 저장소 주소만 된다.
- **전 세계 사람 랭킹** — 공개는 프로젝트 설명과 기여도를 보여주는 것이고, 사람 전체 순위는 아니다. Source: `scope.md > Later`.
- **파일로 프로젝트나 문서를 직접 올리기** — Source: `scope.md > Later`.
- **GitLab 등 GitHub 밖 연동** — Source: `scope.md > Later`.

## Possible Later Enhancements

비공개 저장소를 웹훅으로 붙이는 것, 사이트 전체의 사람 랭킹, 파일 업로드, GitLab 연동은 아직 나중에 할 수 있는 일이다. 계정 로그인은 `4-spec`에서 지금 범위로 가져왔다.

## Non-Goals

- **역할마다 다른 화면이나 권한** — 팀원, 팀장, 평가자는 같은 결과를 본다. Source: `scope.md > Explicitly Cut`.
- **공유 전 화면의 기본값을 전 세계 랭킹으로 두기** — 목록은 그 프로젝트 목록이다. Source: `scope.md > Explicitly Cut`.
