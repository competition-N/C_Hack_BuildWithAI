앱 지도 — 팀 프로젝트 기여도

공개 GitHub 저장소를 넣으면, 모델이 사람마다 커밋을 읽고 기능별로 점수를 매기는 앱입니다. 이 페이지는 나중에 코드를 고치러 돌아왔을 때 어디부터 열면 되는지 알려 주는 안내서입니다.

큰 조각

  • 화면 — public/. 한 페이지 앱입니다. app.js가 화면을 그리고, i18n.js에 한국어·영어 문장이 있습니다.
  • 서버 — server.js. 모든 /api/... 경로, 보안 헤더, 한 시간 판단 횟수 제한을 맡습니다.
  • 판단 — src/github.js(GitHub에서 읽기), src/groq.js(모델에게 커밋 읽히기), src/injection.js(조작 문장 거르기), src/commits.js(커밋별 결과 저장), src/score.js(점수 계산), src/review.js(점수 확인 필요 경고).
  • 저장 — src/db.js가 SQLCipher로 암호화한 data/app.db를 엽니다. src/repos.js가 판단 결과와 순위를 읽고 씁니다.
  • 계정 — src/auth.js(비밀번호, 세션, 로그인 잠금), src/account.js(닉네임, 공개, 언어), src/oauth.js(GitHub 연결).

한 동작 따라가기: 메인에서 "판단하기"

굵은 파란 테두리 두 곳이 아래 경로의 2번, 3번 정류장입니다.

세 정류장 (참고 경로)

이 경로는 아직 함께 따라가 보지 않은 참고용입니다. 편집기에서 파일을 열고 이름으로 찾으면 됩니다. 줄 번호는 2026-10-22 점수 검사를 넣은 커밋 기준이며 코드가 바뀌면 달라질 수 있습니다.

  1. 1. 버튼을 누르면 — public/app.js

    찾기: function bindMain (약 736줄)

    판단하기 폼이 주소를 /api/judge로 보냅니다. 기다리는 동안 busy()가 버튼을 막고, 429(한 시간 횟수 초과)나 400(주소 형식이 틀림)이면 안내 문장을 띄우고, 성공하면 result에 담아 render()로 다시 그립니다.

    const { response, payload } = await api("/api/judge", { method: "POST", body: JSON.stringify({ url }) });

  2. 2. 서버가 순서를 정하면 — server.js

    찾기: async function judgeRepo (약 240줄), 경로는 url.pathname === "/api/judge" (약 441줄)

    판단 한 번의 전체 순서가 이 함수 하나에 있습니다. 저장된 커밋 결과를 먼저 열고, GitHub에서 읽고, 아직 읽지 않은 커밋만 모델에 보내고, 그 결과를 저장한 뒤 점수를 계산합니다. 경로 쪽에서는 결과의 GitHub 아이디를 anonymousPeople로 랜덤 닉네임으로 바꿔서 돌려줍니다.

    const analysis = commitAnalysisReader(db);
const inspected = await inspectRepo(url, { isCached: analysis.has });
const fresh = await analyzePeople(inspected.contributions, analysis);
// ...
const people = scorePeople(inspected.contributions, analysis);

  3. 3. 점수가 정해지면 — src/score.js

    찾기: function scorePeople (25줄), function featuresFor (9줄)

    모델이 읽은 커밋을 (기능, 기술)로 묶고, 기능마다 난이도를 더합니다. 그래서 기능 점수는 (커밋 수 × 난이도)가 되고, 사람 점수는 기능 점수의 합입니다. 모델이 읽지 않은 커밋은 analysis.get이 비어 있어 빠지므로 0점입니다. 화면의 "모델이 읽지 않은 커밋 N개는 점수에 넣지 않음"은 unreadCommits에서 나옵니다.

    group.commits += 1;
group.points += row.difficulty;

이걸 바꾸려면 여기부터

바꾸고 싶은 것시작할 곳
한 시간 판단 횟수.env의 JUDGE_LIMIT_PER_HOUR(계정), JUDGE_LIMIT_PER_IP_HOUR(IP). 세는 방식은 server.js의 takeJudgeSlot
모델이 읽는 사람 수, 사람당 커밋 수src/github.js의 SAMPLED_PEOPLE, LISTED_PER_PERSON. 새 커밋 수는 src/groq.js의 NEW_COMMITS_PER_PERSON
AI 에이전트로 보는 계정 이름src/github.js 맨 위의 AGENT_LOGIN
지우는 조작 문장src/injection.js의 INJECTION_PATTERNS
"점수 확인 필요" 경고 기준src/review.js의 reviewPerson과 맨 위 상수(HIGH_DIFFICULTY, TINY_CHANGE_LINES, TRIVIAL_MESSAGE 등). 문장은 public/i18n.js의 review.*
점수 계산식src/score.js의 featuresFor. 바꾸면 메인 설명(public/i18n.js의 guide.*)도 같이 고칩니다
화면 문장, 난이도 설명public/i18n.js. 한국어와 영어가 같은 키를 씁니다(guide.level1 등)
서버 오류 문장src/messages.js
색, 글자, 간격design/tokens/*.md에 먼저 적고 public/styles.css의 :root를 맞춥니다

다시 쓸 수 있는 방법

"같은 입력이면 같은 결과"를 눈에 보이는 기준으로 정하고 확인하기.

같은 저장소를 판단할 때마다 점수가 25 → 13 → 17로 흔들렸습니다. 모델은 매번 조금씩 다르게 답하기 때문입니다. "같은 커밋은 늘 같은 점수"를 기준으로 정하고, 커밋 SHA마다 결과를 저장해(src/commits.js의 commitAnalysisReader, saveCommitAnalysis) 새 커밋만 모델에 보내게 바꿨습니다. 그다음 같은 저장소를 세 번 판단해 13점이 그대로인 것을 확인했습니다. 기록은 devpost/checklist.md의 Revisions에 있습니다.

다른 프로젝트에서도 AI 모델이 결과를 내는 곳이면, 먼저 "같은 입력을 두 번 넣으면 무엇이 같아야 하는가"를 적고, 실제로 두세 번 넣어 확인해 보세요. 흔들리면 결과를 입력의 고유값(여기서는 커밋 SHA)으로 저장해 다시 쓰는 방법이 있습니다.

다시 실행하기

  1. .env.example을 .env로 복사하고 값을 채웁니다. SQLCIPHER_KEY와 SESSION_SECRET이 없으면 서버가 시작하지 않습니다.
  2. npm install 후 npm start를 실행합니다.
  3. 브라우저에서 http://localhost:3000을 엽니다. public/index.html을 파일로 직접 열면 동작하지 않습니다.

자세한 설정(GitHub OAuth App, 배포)은 README.md에 있습니다.

이 지도에 대해

2026-10-22 점수 검사(src/review.js)를 넣은 커밋의 코드를 보고 만든 스냅숏입니다. 코드가 바뀌면 이 지도와 어긋날 수 있습니다. 함수 이름으로 찾으면 줄 번호가 달라져도 찾을 수 있습니다.
