04 · SPEC · 검토용 초안

무엇을 만들지에서
어떻게 만들지로.

Next.js + Supabase + Vercel. 4단계 기술 계획만 작성했습니다. 앱 코드와 서비스 설정은 시작하지 않았습니다.

구조와 데이터 흐름

React 화면목록·상세·설정
↔
Next.js 서버소유권 확인·분석·점검
↔
Supabase로그인·계정별 저장
GitHub 공개 코드동일 커밋의 파일 → 정적 분석
Vercel 일일 예약활성 설정 확인 → 지정 주소 조회 → 판정 저장

코드 분석과 실제 응답 점검은 별도 경로이며, 각각의 실행 시점을 보여줍니다.

흐름 따라가기

구성요소 · 동작과 파일 연결

API 탐지 · 실행하지 않고 코드 읽기

Babel 구문 분석으로 fetch·axios와 OpenAI·Supabase·Stripe 호출을 찾습니다. 상수·템플릿·제한된 파일 간 import를 추적하고, 실행 중 값은 미해결로 표시합니다. 기능은 함수명과 호출 위치를 근거로 보여줍니다.

파일: src/lib/analyzer/ 및 adapters/. PRD: API 목록과 상세.

로그인과 저장 · 다른 기기에서 이어 보기

Supabase Auth GitHub 로그인. RLS와 서버 소유권 검증을 함께 적용합니다. 마지막 성공 분석 하나와 최근 시도 상태를 분리해 실패 시 성공 결과를 유지합니다.

파일: src/lib/supabase/, data/, supabase/migrations/. PRD: 계정별 동기화, 결과 저장과 교체.

인증 정보 · 점검에만 사용

인증 없음·Bearer·API 키 헤더를 제안합니다. 서버에서 AES-256-GCM 암호화하고 키는 DB와 분리합니다. 비밀값 재노출과 로그 기록은 차단하며 교체·삭제를 지원합니다. 서버 탈취 위험까지 없어지는 것은 아닙니다.

파일: checks/credentials.ts. PRD: Credential Boundaries.

외부 요청 · 주소 검증과 조건 판정

HTTPS GET, 리디렉션 미추적, 사설·예약 IP 차단과 DNS 연결 주소 고정. 10초 제한, 본문 256 KiB, 재시도 없음. 기본 2xx 또는 지정 코드 및 JSON 필드 조건 하나를 검사합니다.

파일: checks/guard.ts, request.ts, evaluate.ts. PRD: Check Criteria.

하루 한 번 · 무료 플랜에서 가능한 크기

전역 cron 하나, 한국 09시대 실행을 제안합니다. 정확한 24시간 간격은 보장하지 않습니다. 기본 켜짐이며 서버가 시작 전 설정을 다시 확인합니다. 중복 실행을 막고 미처리 대상을 완료로 표시하지 않습니다.

파일: api/cron/checks/route.ts, checks/scheduler.ts. PRD: Scheduled API Checks.

검토할 제안 한도

  • 분석: 소스 100개, 파일당 200 KiB, 총 5 MiB, 60초
  • 점검: 사용자당 5개, 배포 전체 20개, 동시 2개
  • JSON 조건 1개, GET·HTTPS만, 고정 키·토큰만
  • 정적 import 추적 깊이 5, 동적 실행과 OAuth 갱신 제외

무료 단일 실행으로 무제한 검사를 약속하지 않습니다. 한도를 넘으면 이유를 표시하고, 큰 규모는 별도 작업 실행 구조로 확장해야 합니다. 앱 요구사항이 늘어 원래 2~4시간 목표를 초과할 가능성이 높습니다.

구현 전에 확인할 증거

탐지 예제와 실제 코드 위치 비교 → 두 계정의 데이터 격리 → 실패 시 이전 분석 보존 → 점검 판정과 외부 요청 보호 테스트 → 예약 중복·비활성화 검증. 무료 플랜 조건, 라이브러리 버전·호환성, 실행 시간 제한은 구현 시작 시 다시 확인합니다.

향후 순서: 탐지 → GitHub 연결과 화면 → 계정·저장 → 인증 점검 → 일일 예약. 지금은 이 작업을 실행하지 않습니다.

디자인과 실행

Docker Desktop 참고, 네이비·크림 팔레트, 한국어 UI, 좌측 API/우측 상세. 구현 후 로컬에서 npm run dev로 실행하고 Vercel에 배포합니다. 필요한 설정명과 전체 파일 구조는 기준 문서에 있습니다.
