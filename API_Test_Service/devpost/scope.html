승인된 범위

공개 GitHub 저장소 주소 하나로 외부 API를 찾아 모으고, 어떤 파일과 기능에서 호출하는지 코드 근거와 함께 보여주는 개발자 도구입니다.

작동을 입증하는 장면

외부 API 호출이 있는 예제 저장소를 분석하고, 목록의 호출 위치를 실제 코드와 비교합니다. 프로젝트의 외부 연동 현황을 파악할 때 이 흐름을 다시 사용합니다.

핵심 가치

API 이름만 나열하는 데서 그치지 않고, 프로젝트의 호출 파일 및 관련 기능과 연결합니다. API 문제의 영향을 조사할 출발점을 제공합니다.

이번에 연습할 것

“구현 계획을 작성하는 방법.” 큰 아이디어를 작은 검증 가능한 범위로 나누고, 이후 요구사항과 구현 단계로 연결합니다.

첫 시제품의 경계

지금 · 목록과 호출 위치
  • 공개 GitHub 저장소 하나를 주소만으로 분석합니다.
  • 탐지 가능한 외부 API를 종합해 보여줍니다.
  • 호출 파일과 관련 기능을 코드 근거에 연결합니다.
  • 판단이 어려운 결과는 불확실성을 표시합니다.
나중에 · 보안과 장애 대응
  • 인증 및 접근 권한 보안 분석
  • 장애 대응 코드 분석
  • 별도 실행 환경을 활용한 응답 확인과 장애 테스트

이 단계들은 실행 맥락과 검증 방식에 대한 추가 설계가 필요합니다.

첫 시제품에서 제외 · 이유
  • 비공개 저장소 연결: 공개 저장소 하나로 입력 범위를 줄입니다.
  • 로컬 실행 환경과 인증 정보 연결: 저장소 주소만 입력하는 방식을 선택했습니다.
  • 모든 API의 실제 응답 확정과 장애 주입: 코드만으로 입증할 수 없고 핵심 흐름을 넘어섭니다.

검토가 필요한 한계

실시간 응답 상태는 첫 시제품에서 검증하지 않습니다.

저장소 코드만으로 현재 정상 응답을 확정할 수 없습니다. 상태는 ‘확인 불가’와 이유를 보여주는 것으로 초안에 정리했습니다.

모든 API를 빠짐없이 찾아낸다는 보장도 하지 않습니다. 지원 언어와 탐지 패턴, 관련 기능의 표시 방식은 다음 요구사항·기술 계획 단계에서 구체화합니다.

아직 정하지 않은 것

지원할 저장소의 언어와 규모, 외부 API 탐지 기준, 결과 화면과 오류 처리, 시각적 스타일. 이 페이지의 디자인은 계획 검토용이며 제품의 디자인 결정은 아닙니다.
