03 · PRD · 승인됨

저장소에서 API까지,
사용 흐름을 구체화했습니다.

GitHub 계정으로 저장소와 마지막 성공 결과를 이어 보고, API별 호출 위치를 확인하는 도구.

전체 여정

GitHub 로그인→저장소 목록·추가→자동 / 수동 분석→API 목록·상세→계정에 결과 저장

같은 계정으로 다른 기기에 접속해 목록·설정·결과를 이어 봅니다.

화면과 동작 펼쳐보기

저장소 목록과 등록

이전에 등록한 저장소 목록과 ‘새 저장소 추가’ 버튼을 표시합니다. 첫 사용은 빈 목록에서 시작합니다. 공개 GitHub 저장소 주소를 입력해 등록하고 결과 화면으로 이동합니다.

확인 기준

다른 기기에서도 같은 계정의 목록이 보이고, 다른 계정의 개인 목록은 보이지 않아야 합니다.

자동 분석 설정

기본값은 켜짐. 등록하면 바로 분석합니다. 계정 설정에서 끄면 등록만 하고 수동 실행합니다. 설정도 계정에 저장합니다.

확인 기준

켠 상태에서 즉시 분석, 끈 상태에서는 수동 실행 전까지 미분석으로 구별됩니다.

API 결과와 상세
왼쪽 · API 목록

탐지한 API 중 하나 선택

오른쪽 · 선택한 API
  • API 식별 정보
  • 호출 파일과 관련 기능·코드 근거
  • 최근 점검 결과·시점 또는 미설정 이유

확인 기준: 왼쪽 선택에 따라 상세가 바뀌고, 예제 저장소의 실제 코드와 호출 위치가 대응해야 합니다. 관련 기능을 판단하기 어려우면 불확실성을 표시합니다.

상태와 오류
  • 분석 중: ‘분석 중’만 표시
  • 실패: ‘분석 실패’와 실제 확인한 사유
  • 미검출: 실패로 안내하되 ‘지원하는 탐지 방식으로 찾지 못함’으로 표현
  • 로그인·저장 오류: 이유를 안내하고, 저장 실패를 성공으로 표시하지 않음

API 미검출은 API가 없다는 증거가 아니며, 과거 분석 결과는 실시간 상태가 아닙니다.

결과 보존 규칙 · 예시로 확인

아래 버튼은 실제 분석이 아닌, 합의한 저장 규칙의 예시입니다.

성공 결과는 하나만 보관합니다. 최근 시도의 상태와 마지막 성공 결과를 별도로 저장하며, 실패할 때 기존 성공 결과를 지우지 않습니다.

범위 변경과 한계

기존 범위에 GitHub 로그인과 계정별 목록·설정·결과 동기화를 추가했습니다. 여러 개발 환경에서 반복 등록을 피하기 위한 사용자 결정입니다. 계정 기능으로 작업량이 늘었으며 기술 계획에서 2~4시간 목표를 재평가해야 합니다.

실제 API 점검은 아래 변경안으로 추가합니다. 비공개 저장소, 보안·권한 자동 분석, 장애 주입 테스트, 여러 분석 이력은 계속 제외합니다. 사용법 안내는 나중에 추가합니다.

기술 계획에서 정할 것

지원 언어·탐지 패턴·저장소 규모, 기능 설명 근거, 무료 데이터베이스와 웹 배포 이용 조건, GitHub 로그인과 계정별 접근 제어. Supabase와 Vercel은 희망 서비스이며 아직 기술 선택을 확정하지 않았습니다.

추가 변경안 · 하루 한 번 실제 API 점검

사용자가 지정한 점검 주소와 읽기 전용 API 키·고정 토큰으로 등록 대상 전체를 하루 한 번 검사합니다. 자동 점검은 기본으로 켜져 있으며 계정 설정에서 끌 수 있습니다. 변경한 설정은 같은 계정의 다른 기기에도 유지됩니다. 정확한 24시간 간격은 보장하지 않습니다.

정상 판정 기준
  • 기본: HTTP 2xx면 설정한 기준 통과
  • 선택 조건: 예상 상태 코드와 JSON 필드의 예상 값. 지정 조건 모두 충족해야 통과
  • 예: 200 + status=ok는 통과, 200 + status=error는 미충족
  • 필드 누락·비JSON은 설정 조건에 따라 미충족, 시간 초과는 실행 실패

서비스 전체 정상이라고 단정하지 않습니다. 최근 점검 시점·응답 코드·응답 시간을 분석 결과와 구별해 저장합니다.

인증 정보와 범위

읽기 전용 키·고정 토큰만 지원. 권한 자동 판별과 OAuth 갱신은 제외합니다. 비밀값은 다시 노출하지 않고 교체·삭제할 수 있어야 합니다. 서버 측 암호화와 계정별 접근 제어, 전송 대상 제한은 기술 계획에서 구체화합니다.

기존 scope의 실제 점검 제외 결정을 대체하는 승인된 요구사항입니다. 계정·예약·인증 정보 관리로 작업량이 늘어 원래 2~4시간 목표를 재평가해야 합니다. 자동 점검은 기본 켜짐으로 확정했습니다.
