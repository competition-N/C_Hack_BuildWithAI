## Title

Team Contribution: score each person's GitHub work by feature, with a public ranking

## Body

### Summary

Team Contribution reads a public GitHub repository and shows who actually built what. It is made for university team projects, where one or two people often carry the work.

A language model reads each person's commits and assigns each commit to a feature, a technology, and a difficulty from 1 to 5. A person's score is the sum, over their features, of (commits × difficulty). Commits the model did not read add zero points.

This PR adds the whole proof of concept built for the Devpost **Build With AI: Basics** hackathon, along with its planning documents.

Live site: [https://남단추.kro.kr/project/project-score/](https://xn--q20bs6bj07b.kro.kr/project/project-score/)

### What's included

**Judging**
- Paste a public GitHub URL on the main page to get each person's score, per-feature points, and evidence (commits, merged PRs, files and lines read).
- A repository briefing: tech summary, features, difficulty with reasons, and algorithms.
- AI agent commits (`cursoragent`, `copilot*`, `claude*`, `codex*`, `devin*`, `[bot]`) are credited to the human in `Co-authored-by`.
- Each commit's result is stored by SHA, so judging the same repository again only reads new commits and old scores do not change.
- **Score review warnings.** When the model's ratings do not match the evidence, the person is marked "Score needs review" with the reasons. The checks: instructions about the score in a commit message, typo/docs/rename commits rated 4+, tiny or docs-only commits rated high, and almost every commit at the top level. Scores are not changed automatically.

**Ranking**
- A public contribution ranking across all judged repositories, with nickname search and a page for each person.
- People appear under a random nickname (for example `CalmOtter#4a1f`) unless they connect GitHub and make their account public.

**Accounts**
- Sign up and sign in. Settings: nickname, password, public account, language, GitHub connect/disconnect, delete account.
- GitHub OAuth connect proves which GitHub user you are. It requests no scopes and does not keep the token.
- My projects: add repositories from your own GitHub repository list and see only your own contribution. Each project has a "Show in the public ranking" switch.

**Interface**
- Single-page interface in Korean and English, switched with the **Language: KR / EN** button.
- Design tokens in `design/tokens/` with WCAG AA contrast, one `h1` per screen, visible labels, and three layout widths.

**Docs**
- English `README.md` with the live site link, run instructions, environment variables, GitHub OAuth App setup, and steps for deploying, including under a sub-path of an existing site.

**Deployment**
- The app runs at a domain root or under a sub-path such as `/project/project-score/`. API calls are relative to the page, and the server reads its path from `PUBLIC_URL`. The login cookie and the GitHub sign-in return address follow that path.
- `devpost/`: scope, PRD, spec, build checklist, and `app-map.html`, a guide to where the code for each part lives.

### Security

- The database (`data/app.db`) is encrypted with SQLCipher (AES-256). The server refuses to start without `SQLCIPHER_KEY` and `SESSION_SECRET`.
- Passwords are hashed with Argon2id. Five wrong passwords lock the account for 15 minutes.
- Sessions are stored on the server. Cookies are `HttpOnly` and `SameSite=Lax`, and also `Secure` when `PUBLIC_URL` is HTTPS.
- Security headers on every response: a strict CSP (`self` only, `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP, and HSTS on HTTPS.
- Judging is limited to 3 per hour per account **and** per IP address, so creating extra accounts does not add judgments. The IP limit can be raised separately with `JUDGE_LIMIT_PER_IP_HOUR`.
- Text from repositories is scrubbed of prompt-injection phrases before it is sent to the model, and the model is told to treat it as data only. Because a pattern filter cannot catch every phrasing, ratings that do not match the evidence get a "Score needs review" warning.
- Error messages tell the user what went wrong without exposing internals.
- OAuth `state` is single-use and expires after 10 minutes. A GitHub account can be connected to only one user.
- Static file paths are confined to `public/`.
- `.env` and `data/` are ignored. `.env.example` contains no secrets.

### How to test

1. `npm install`, copy `.env.example` to `.env`, and fill in the keys as described in the README.
2. Run `npm start` and open `http://localhost:3000`.
3. Judge a public repository on the main page and check the per-feature scores and briefing.
4. Judge the same repository again. "0 new commits analyzed" should appear and the scores should not change.
5. Open **Public ranking**, search a nickname, and open a person.
6. Create an account, connect GitHub in **Manage → Settings**, then add a repository in **Manage → My projects** and hide it from the ranking.
7. Switch the language with the button at the bottom of the left menu.
8. Judge 3 times from one network, then create a new account and judge again from the same network. The fourth judgment should be refused with 429.

Checks already run:
- `npm audit --omit=dev`: 0 vulnerabilities.
- A fresh copy started from `.env.example` alone: the server started with an empty ranking, and `data/app.db` was encrypted.
- Login lockout: the sixth attempt after five wrong passwords returns 429.
- The same repository judged three times kept the same score.
- Judging limit: on a separate test server, a new account on the same IP was refused once the IP limit was reached.
- Score review: with test data, a manipulated record got all four warnings and an honest one got none. The injection patterns caught 10 of 10 manipulation phrases and flagged none of 8 normal commit messages. A real re-judge of a public repository kept its score and got no warning.
- 7 screens × 1280 / 900 / 390 px: no script errors.
- History of this branch scanned for token patterns: none found.

### Known limitations

- Only public GitHub repositories. Private repositories and GitLab are not supported yet.
- Per judgment, the model reads up to 25 recent commits for each of the 6 people with the most commits. People outside the top 6 get 0 points.
- Without `GROQ_API_KEY`, the app runs but every score is 0.
- Rate limits, login lockouts, and OAuth state are kept in memory. They reset on restart and assume a single server process.
- Anyone can lock an account by entering five wrong passwords for it. This is a known trade-off of the lockout.
- People on the same network share the IP judging limit. On a campus network, raise `JUDGE_LIMIT_PER_IP_HOUR`.
- Random nicknames hide GitHub usernames, but a person's page lists their repositories. In a repository with few contributors, someone could match the nickname with the repository's contributor list on GitHub.
- Score review warnings are rule-based and can be wrong in both directions. The "tiny change" check only applies to commits whose code was read after this change.

### Before deploying

- Use new `SQLCIPHER_KEY` and `SESSION_SECRET` values, and start with an empty `data/` folder.
- Set `PUBLIC_URL` to the HTTPS address and `TRUST_PROXY=1` behind a reverse proxy.
- Create a separate GitHub OAuth App with `https://<your-site>/api/github/callback` as the callback URL.
